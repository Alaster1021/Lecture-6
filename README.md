# Практическое задание по Git: Работа с ветками и Rebase


---

## Условия задач

### Задача 1 (Тип 16 № 37841)
Напишите программу, которая в последовательности натуральных чисел определяет **сумму чисел, оканчивающихся на 3**.
Программа получает на вход количество чисел в последовательности, а затем сами числа.
*Пример работы:*
- **Вход:** 3 (количество чисел), далее: 13, 23, 24
- **Выход:** 36 (так как 13 + 23 = 36)

### Задача 2 (Тип 16 № 37906)
Напишите программу, которая в последовательности натуральных чисел определяет **сумму чисел, кратных 6 и оканчивающихся на 4**.
Программа получает на вход количество чисел в последовательности, а затем сами числа.
*Пример работы:*
- **Вход:** 3 (количество чисел), далее: 24, 25, 54
- **Выход:** 78 (так как 24 и 54 кратны 6 и оканчиваются на 4, 24 + 54 = 78)

---

##  Описание веток в репозитории

1. **`master`** — здесь находится итоговый, чистый и рабочий вариант. Изначально в этой ветке лежали только условия задач. Потом Никита Владимирович добавил решщение первой задачи, но к сожалению с ошибкой. Ваша задача будет поправить ее в ветке hotfix.
2. **`hotfix`** — ветка, которая отпочковалась от старой (ошибочной) версии `master`. В ней надо исправить баг в Задаче 1 от Никиты Владимировича.
3. **`task-2`** — ветка, в которой параллельно велась разработка решения для Задачи 2 (`task2.py`).

---

##  Ваше задание

Ваша цель — объединить наработки из веток `hotfix` и `task-2` в ветку `master` с помощью `git rebase`, чтобы история изменений получилась красивой и линейной.

### Пошаговый алгоритм:
1. **Сделайте форк моего репозитория**
1. **Клонируйте свой форк  репозитория.**
2. В ветке hotfix пофиксите баг Никиты Владимировича
3. В ветке task-2 напишите решение второй задачи.
4. Объедините ветки с помощью git rebase.
5. Запушьте ваши результаты и вставьте ссылку на ваш форк. 

После выполнения этих шагов в вашей ветке `master` должны успешно находиться два файла: исправленное решение первой задачи и новое решение второй задачи, а история коммитов в `git log --oneline --graph` должна быть абсолютно линейной!
